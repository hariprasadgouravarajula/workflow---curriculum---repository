## 4. Reasons (11)
- **R1 Visualisation and dashboards** appear in 3 of 3 postings and no current course teaches BI tools. ADD Data Viz and BI (sem VI, after Data Science); UPDATE Data Science.
- **R2 SQL** appears in 3 of 3 (JD-2 adds ORM). UPDATE DBMS toward query tuning, ORMs and realistic schemas.
- **R3 Python with data libraries** appears in 3 of 3. UPDATE Industry Coding Practice toward pandas/NumPy workflows, testing and clean code.
- **R4 ML methods and libraries** appear in 3 of 3. UPDATE Machine Learning toward model evaluation and scikit-learn pipelines. Deep Learning, NLP and CV stay because JD-1 names all three and JD-2 names DL libraries.
- **R5 Git and clean code** appear in 1 posting each (weak evidence) but underpin every other lab and nothing covers them. ADD a 2-credit Tools Lab in sem I.
- **R6 Cloud and data pipelines** appear in JD-1 (Azure, pipelines) and JD-3 (large-scale processing). ADD MLOps and Cloud Deployment Lab (sem VII; builds on Cloud Computing, ML, Big Data Systems).
- **R7 Responsible AI use** is not in the postings. The basis is the five AI exercises: all were correct only because each had an independent check (`ai-exercises/`). ADD a 2-credit course in sem II, as a co-requisite of Introduction to AI and DS.
- **R8 Advanced CS topics absent from all three postings** (compiler construction, theory of computation, blockchain, signal processing): trim 1 credit each, keep core ideas.
- **R9 Foundation overlap:** engineering graphics, electronics, digital fabrication, physics, chemistry and social change appear in 0 of 3 postings; trimmed lightly. Likely regulated (see section 6).
- **R10 Load balance:** semesters II, IV and V carry 24 credits and VII carries 16. Moving credits down in II-V and adding in VI-VII evens the load.
- **R11 Integration:** one capstone lab turns the Task 1 workflow into a team project covering pipelines, testing and communication (JD-1 and JD-2 themes), and uses the light semester VII.

## 7. Capstone lab: Workflow Automation (from Task 1)
3 credits, sem VII. Teams of 3 choose a campus process (default: certificate requests), map it from permitted observation, build a status-based prototype like `../task1-certificate-workflow/workflow.py`, and test it on five synthetic cases (normal, missing information, duplicate, unauthorized, failed step). Assessment: evidence log 25%, process design with owner and approval boundary 25%, tests and recovery 25%, net-time calculation with sensitivity 15%, AI-use record 10%. Only synthetic data; no names, IDs, marks or fees.
